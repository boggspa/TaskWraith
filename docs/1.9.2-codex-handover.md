**1. `WorkspaceLockMcpControlPlane` / admission context parameterisation**

```

  'marker' does not exist in type 'WorkspaceLockMcpAdmissionContext'
```

The test constructs `new WorkspaceLockMcpControlPlane<TestContext>(...)` and
passes a context carrying `marker: 'preserved'` — i.e. it asserts an extra field
survives admission. `WorkspaceLockMcpAdmissionInput<Context>`
(`WorkspaceLockMcpAdmissionCoordinator.ts:81`) *is* generic, but the
**coordinator class at :125 is not**, and `WorkspaceLockMcpControlPlane.ts:55`

parameter while both adjacent members carry `<Context>`:

```ts
readonly externalMutationAuthority: WorkspaceExternalMutationAuthorityIssuer<Context>
readonly admission: WorkspaceLockMcpAdmissionCoordinator      // <- no <Context>

```

**I tried adding `<Context>` and it was wrong** — TS2315, the class is not
generic. So the choice is genuinely open: either the coordinator becomes
context-parameterised like its siblings, or the test should not pass `marker`.
Those differ in whether admission is meant to be context-transparent. Codex
decides.
